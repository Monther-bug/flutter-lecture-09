Stateless

How a StatelessWidget works

lib/warmup/greeting.dart
class Greeting extends StatelessWidget {
  const Greeting({super.key, required this.name});

  final String name;

  @override
  Widget build(BuildContext context) {
    return Text('Hello, $name!', style: const TextStyle(fontSize: 24));
  }
}

// Using it:
const Greeting(name: 'Ali'),
const Greeting(name: 'محمد'),
1Data comes inthrough the constructor; the fields are final.
2build() runswhen the parent rebuilds it, maybe with new data.
3Each use, its own data'Ali' and 'محمد': same class, different name.
It can never change its own name.

Watch out

Common mistakes

The error or symptomThe fix
The method 'setState' isn't defined for the type 'CounterPage'.It is a StatelessWidget. Convert it to a StatefulWidget.
Console shows the new value, the screen does notWrap the change in setState(() { … });
The named parameter 'email' is required, but there's no corresponding argument.Pass the data: HomePage(email: email)
The argument type 'HomePage' can't be assigned to the parameter type 'Route<Object?>'.Wrap the page: MaterialPageRoute(builder: (context) => HomePage(email: email))
Coming later: Navigator.pushReplacement (go to Home with no way back to Login) and named routes.
Mobile App Development · Lecture 09

Make one of these mistakes on purpose and read the red message together. Real apps use pushReplacement after login so "back" does not return to the login form; we will meet it in the Firebase lectures.

Wrap-up

Summary + Questions

Remember

  • Stateless = shows what it is given. Stateful = remembers data that can change.
  • A StatefulWidget = 2 classes; the State keeps the data.
  • Change a State field inside setState(), or the screen will not update.
  • Screens sit on a stack: Navigator.push adds, Navigator.pop removes.
  • Send data to a screen through its constructor.
